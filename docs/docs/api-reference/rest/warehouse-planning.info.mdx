Can this warehouse process the demand assigned to it, given its current labor, location, equipment, station, conveyor and buffer constraints? Phase 1 exposes native ProcessCapacity registration and the computed effective rate; Phase 2 the normalized ProcessPath capacity; Phase 4 CapacityPlans (assigned demand vs. path capacity, shortage, bottleneck) whose lifecycle events leave through a transactional outbox (see asyncapi.yaml). Station capacity: stations tallied from facility-layout have no throughput of their own; an operator-declared StationStandard (throughput per station) is composed with LABOR and the other constraints AT READ TIME (docs/adr/0002), and the storage positions / station counts of a site are a read model.
Cross-cutting behaviour of the service on port 8080: errors are RFC 7807 application/problem+json. A NUL character (U+0000) in the path is 404 resource-not-found, in the query 400 malformed-request-query and in a request body 400 malformed-request-body. A collection GET answers 400 unknown-query-parameter for a query parameter it does not declare; the other GETs ignore unknown parameters. A request body is parsed as JSON whatever its Content-Type, and unknown body fields are ignored. Every POST is keyed by Idempotency-Key; the PUT declarations are naturally idempotent and take no key. A request to an unrouted path or method is answered by the router with a plain-text 404 / 405 outside this contract. GET /healthz and GET /readyz exist but are operational probes, not part of this contract.
